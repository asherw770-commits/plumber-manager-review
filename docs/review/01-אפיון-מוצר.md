# אפיון מוצר

## 1. רקע עסקי
- **העסק:** "יהודה קליין אינסטלציה" — אינסטלטור עצמאי. הכנסות מעבודות אצל לקוחות פרטיים. מעט חומרים (לרוב נרכשים בנפרד ומתועדים כ"הוצאה" או כ"חומרים" על העבודה).
- **שותפים:** אינסטלטורים אחרים. שני כיוונים:
  - **הלקוח שלי** — יהודה מקבל עבודה מלקוח, ושותף מבצע חלק ממנה (או כולה). יהודה גובה מהלקוח ומעביר לשותף את חלקו.
  - **לקוח של שותף** — השותף מקבל עבודה ויהודה מבצע; השותף גובה ומעביר ליהודה את החלק שלו (או יהודה גובה ומעביר לשותף את חלקו).
  שני המספרים (כמה אני חייב לשותף / כמה הוא חייב לי) מוצגים **בנפרד, בלי קיזוז**.
- **אין מע"מ:** בוטל ב-16.9.2026; כל הסכומים הם הסכום הסופי (בקוד נשארו שרידים של שדות מע"מ ישנים — `noVat`).
- **בסיס ההכנסה:** הכנסה שייכת לחודש שבו בוצעה העבודה (שולם או לא). "שולם" מסומן רק אחרי שהכסף נכנס בפועל.
- **כלל גבייה:** תשלום מזומן מיד בסיום העבודה, או העברה/ביט, או מזומן לבית. כל מה שפתוח אחרי יום העבודה הוא "חריגה" (נמדד במסך הגבייה, כרטיס "עמידה בכלל").

## 2. המשתמשים והתפקידים
| תפקיד | מי | מה הוא עושה |
|---|---|---|
| `admin` | אשר — מזכיר/מזין נתונים | כל הפעולות: מזין ומעדכן עסקאות, גבייה מול לקוחות ושותפים, ניהול משתמשים והרשאות, הגדרות, דוחות, ייצוא. הוא המקור היחיד לכתיבה בברירת המחדל. |
| `manager` | יחיאל — יועץ עסקי | **קריאה בלבד** במסכי הכסף (סיכום כספי, רווחיות, שווי שעה, עסקאות, לקוחות, שותפים). יכול להשאיר הערות לאשר. |
| `owner` | יהודה — בעל העסק (טלפון) | מסך בית פשוט: העבודות של היום, "לקוח שילם לי", הזמנות מלקוחות והתראות. כל מה שהוא מסמן עובר **לתור אישור אצל אשר** (`state/owner_actions`) — אלא אם הופעל המתג "יהודה מכניס בעצמו" (`state/config.yehudaDirect`), ואז יש לו כתיבה ישירה מוגבלת. |
| משתמש עם `access` | כל משתמש שהאדמין הגדיר לו לשוניות | הרשאה **לפי לשונית** (ניווט בלבד — ראה אבטחה, סעיף מגבלות). |

ברירות המחדל של הלשוניות לכל תפקיד והשינוי שלהן נבדקים ב-`tests/access-check.js`.

## 3. המסכים (view-id בקוד)
| מסך | `view` | מה הוא מציג |
|---|---|---|
| בית | `dashboard` | אצל אשר **בלי כסף**: עבודות שבוצעו החודש והשבוע (מול קודם), שעות, כמה עבודות לגבייה וכמה ימי איחור, שותפים עם יתרה, "מחכה לך", בדיקות מערכת. אצל יהודה: עבודות היום וכפתורים. |
| משימות/יומן | `tasks` | עבודות מתוזמנות ותזכורות; כרטיס עבודה עם חייג/וואטסאפ/"אני בדרך". |
| גבייה | `collection` | תור הגבייה: עסקאות שבוצעו ולא שולמו (או חלקי), לפי ימי איחור; כלל הגבייה. |
| עסקאות | `transactions` | יומן כל העסקאות עם סינון לפי חודש/סטטוס; עריכה; שורת "מגיע לי" ותגיות (שותף ועוד). |
| סיכום כספי | `reports` | **חמישה מספרים בלבד** לתקופה שנבחרה (כל העבודות שבוצעו בה): הכנסות, הוצאות (חלק שותפים + חומרים + הוצאות), רווח סופי (= הכנסות − הוצאות), נגבה ולגבייה (נגבה + לגבייה = הכנסות). בלי פירוט נוסף; מכאן אפשר לייצא לאקסל ולהפיק דוח חודשי PDF. |
| רווחיות | `profit` | **לשונית "חודשים ושבועות":** נכנס / יצא (שותפים, הוצאות, חומרים) / סה"כ ביד / שעות; הוצאות לפי קטגוריה וחודש + בדיקות. **לשונית "לפי סוג עבודה":** אחוז רווח לפי קטגוריה וסוג עבודה (משוקלל), רווחיות מוצרי קטלוג. |
| שווי שעה (ERP) | `erp` | כמה שווה שעת עבודה לפי עבודות שנרשמו להן שעות, בפילוח עבודות שלי / עם שותף / בשביל שותף. |
| לקוחות | `customers` | לקוחות נגזרים מהעסקאות + מטא-דאטה (טלפונים, כינויים, "לא כפול"). |
| שותפים | `partners` | לכל שותף: כמה אני חייב לו, כמה הוא חייב לי, התחשבנויות. |
| מחירון / מוצרים | `products` | מחירון יהודה (קבוצות) + קטלוג מוצרים עם עלות/מחיר. |
| הודעות ליהודה | `messages` | הודעות להעתקה/שליחה בוואטסאפ (בוקר, מוצש"ק-גבייה, סיכום שבוע, סיכום יום). לא נשלחות אוטומטית. |
| וואטסאפ | `whatsapp` | תיבת הודעות גולמיות שנסרקות מקבוצת העסק; **לא הופכות לעסקה בלי אישור אשר** (כלל עסקי מפורש). |
| הגדרות | `settings` | משתמשים והרשאות, פרטי תשלום, מתגים (יהודה מכניס בעצמו), הוצאות קבועות, קישור סיווג סוגי עבודה, גיבוי. |
| הוספה | `add` | טופס עבודה/הוצאה חדשה. |

## 4. מחזור החיים של עסקה (`stage`)
`quote` (הצעת מחיר) → `scheduled` (מתוזמן) → `unpaid` (בוצע, לא שולם) → `partial` (שולם חלקית) → `paid` (שולם). `cancelled` מחוץ למסלול. הפונקציה `txStage(t)` היא המקור היחיד; שדות ישנים (`status`, `lifecycleStatus`) נשמרים במקביל לתאימות ויוסרו (ראה חוב טכני). "עבודה שבוצעה" = `unpaid/partial/paid` (`isDoneTx`).

## 5. תהליך עבודה טיפוסי
1. הלקוח פונה (וואטסאפ / טלפון / טופס `/order` ציבורי עם התראה לטלפון של יהודה).
2. נוצרת משימה/עבודה ביומן (אשר, או יהודה דרך תור האישור).
3. העבודה מבוצעת → מסומנת "בוצע" (+ זמן עבודה, חומרים) → הופכת לעסקה `unpaid`.
4. הלקוח משלם (מזומן/ביט/העברה) → "לקוח שילם לי" → `paid`/`partial` עם `receipts` (יומן קבלות) ותאריך תשלום.
5. אם יש שותף: מחושבים החלק שלו; "אני חייב לו" / "הוא חייב לי"; התחשבנויות (`settlements`) מקזזות.
6. אשר מזין/מאשר, והמערכת מסנכרנת: מסך, גיליון Google חי, גיבוי לילי ל-Drive.

## 6. מקורות נתונים נוספים
- **טופס `/order`** (ציבורי) → `orders` (+ `orderPhotos`) → התראת Push ליהודה → "הכנס לעבודות".
- **וואטסאפ** — הודעות מובנות לפי 3 תבניות (`parseWaTemplate`) נכנסות לתיבה בלבד.
- **קישור סיווג סוגי עבודה** (`/classify#t=…`) — הבעלים מסמן לאיזו קטגוריה שייך כל שם עבודה; הסימון חל על כל העבודות עם אותו שם.
- **ייצוא/סנכרון:** קובץ Excel/CSV, גיליון Google חי (`ראשי` ו-`דשבורד` עם נוסחאות), גיבוי JSON ידני וגיבוי לילי ל-Drive.

## 7. דרישות לא-פונקציונליות מוצהרות
- **דיוק מספרים** מעל הכול; כל שינוי במספר כספי חייב לעבור שער בדיקות (ראה `03`).
- **מעט עבודה ידנית** לבעל העסק; **עבודה במכשירים מרובים** (מחשב של אשר + טלפונים) עם עבודה גם בלי קליטה (נתונים נשמרים מקומית ומתמזגים).
- **פרטיות:** נתוני לקוחות (שם, כתובת, טלפון) — מידע אישי. גישה רק למשתמשים מורשים.
- **גודל:** מסמך הנתונים הראשי ב-Firestore מוגבל ל-1MB; כרגע ~216KB (ראה מגבלות).
